# 广工商校园网助手

Windows 小程序：监测断网后先尝试学校的“临时用户登录”，未能恢复上网时自动改用“统一身份认证登录”，支持登录 Windows 后自动启动、系统托盘和密码加密保存。

## 使用

1. 将 `outputs/GGS-WiFi.exe` 放在一个固定位置，双击运行。无需安装 Python、Node 或额外组件；系统需有 .NET Framework 4.8 及 Edge 或 Chrome（Windows 10/11 通常已具备）。
2. 连接校园 Wi-Fi 或校园网线，在右侧“统一身份认证”填写**学号/工号及统一身份认证密码**；在左侧“临时用户登录”填写独立的**临时账号及临时密码**。两组凭据分别加密保存。
3. 默认勾选“优先临时用户登录，失败后使用统一认证账号登录”。临时账号和密码同时留空，或取消此选项，都会直接使用统一认证。勾选“断网后自动认证”和“开机自启”，点击“保存并开始”。这时才会写入当前用户的 Windows 启动项，无需管理员权限。
4. 关闭窗口后继续在右下角托盘运行；双击托盘图标可回到设置，右键可立即检查、暂停/恢复或退出。
5. 需要立即尝试时，点击“立即检查 / 恢复”。改过账号密码后，请先保存。

开机自启指登录当前 Windows 用户后后台启动，默认等待 12 秒让网络就绪。移动 EXE 后请从新位置运行并再次保存，更新启动路径。

更新程序前，请先从托盘菜单退出旧版，再替换 EXE。原有账号、密码归入“统一身份认证”，自启设置会保留；临时账号密码需另行填写，留空时不会拿统一认证凭据尝试临时登录。之前暂停的认证可点击“立即检查 / 恢复”继续。

## 工作方式

- 默认每 30 秒检查一次互联网，连续两次不通才尝试认证；检查间隔可设为 15–300 秒。
- 连通性检测优先使用 Windows 标准 HTTP 检测页，要求状态码 200 且正文完全匹配 `Microsoft Connect Test`；也支持 Apple 的 HTTPS 检测页，并兼容其实际返回的大写 HTML 标签。微软 HTTPS 端点证书异常不会单独触发重复认证，登录页或带“Success”字样的其他页面不会判为联网。
- “保存并开始”或“立即检查 / 恢复”会立即检查并在断网时尝试认证，不额外等待第二次采样。状态说明自动换行，日志可滚动；窗口过小或系统字体放大时，表单自动重排并可纵向滚动查看全部内容。
- 通过 HTTP 连通性入口取得当次校园网跳转，获取学校实时认证配置，并核对客户端 IP 确实属于本机。保留校内网关 `10.20.16.5` 的有效入口；学校域名优先使用 HTTPS，无法获取配置时尝试校内网关。不会保存或复用示例链接中的旧 IP、MAC、VLAN。
- 若 TUN/VPN 等网络环境没有返回校园网跳转，裸网关会返回空的 `portalForm`。程序会尝试以本机当前 `10.*` 校园网网卡地址，向用户提供且已由官方配置核实的控制器 `NFV-BASE-01` 查询配置；只有配置返回相同的本机 IP、控制器身份及有效模板才继续。不会把虚拟网卡的 `192.168.*` 地址或旧链接中的 IP、VLAN 填入此查询。仍建议保留校园内网的直连规则。
- 能识别官方模板的 `logout.html` 跳转，将其中的当前接入参数转回 `/portal.do`。`logout.html` 本身是下线页，其中静态的“认证成功”文案不代表当前已经联网，程序不会点击“下线”。
- 在独立的后台 Edge/Chrome 会话里，先填写官方临时登录表单，勾选网页要求的使用协议，点击“临时用户登录”。保留网页原有的参数、UUID、时间戳和按服务器配置启用的 RSA 加密；不自行拼接密码请求。
- 临时登录仅允许向 `https://net.gzgs.edu.cn/portal.do` 或学校的 `http(s)://10.20.16.5/portal.do` 表单填写账号密码。网页处理加密与请求，校内 HTTP 入口沿用学校提供的传输方式。
- 临时登录失败、超时、需要验证或完成后仍无法联网时，关闭该浏览器会话并重新获取当前认证参数，再打开门户点击“统一身份认证登录”。统一认证的密码只填入 `https://cas.gzgs.edu.cn/authserver/login`，同时核对表单提交地址；隐藏令牌和单点登录回调由官方网站与浏览器处理。
- 每种方式完成后都再次检查互联网，验证通过才报告认证完成，并在日志中区分临时登录和统一认证。网络请求直接连接，不走系统代理。
- 验证码判定以实际可见、可操作的验证码输入框、验证组件或明确的验证错误为依据；短信登录入口、验证说明、隐藏及禁用控件不会单独触发暂停。临时入口的页面加载最多等待 60 秒，避免尚未加载完成就直接切换统一认证。
- 运行记录保留每个登录阶段以及学校临时登录返回的数字代码和归类原因，不记录账号密码、原始服务端消息、请求参数或完整跳转链接。
- 自动关闭网页的普通提示弹窗并识别“非法接入”；涉及确认或输入的弹窗不自动同意。接入参数无效时等待重新获取；统一认证遇到验证码、额外验证、表单不兼容或账号被拒绝时暂停认证，防止循环提交。手动处理后点击“立即检查 / 恢复”。其他临时故障按 30、60、120、240、300 秒递增等待（如果检查间隔更长，则以该间隔为起点）。

**适配状态：**已读取校内网关返回的实际桌面门户、下线页和 `portalUtil.js`，核对临时登录的 `#userid`、`#passwd`、`#read`、`#loginsubmit` 及官方 `checkSubmit` / `encryptParam`。统一认证保留原有 `#fm1`、`#username`、`#password`、`#login`、`execution` 和隐藏短信验证区域的适配。离线测试使用真实表单和官方脚本片段，验证参数保留、加密调用、自动切换、弹窗、取消和旧配置兼容。另已使用已保存的临时账号单次实测，观察到学校成功页，并发现旧版联网探测不识别 Apple 大写 HTML、微软 HTTPS 证书异常的问题，现已修正。统一认证的真实账号登录仍需实际页面验证。若实际运行提示失败，可提供配置目录中的 `activity.log` 继续排查；不要发送密码。

本程序用于完成已有校园网账号的正常认证。Wi-Fi 本身断开、校园网上游故障、账号欠费或网络限制仍需恢复连接或处理账号后才能上网。

## 配置、日志与自启

配置目录：`%LOCALAPPDATA%\GGS_WIFI`。

- `settings.json`：临时登录和统一认证各自的账号、检查选项、Windows DPAPI 分别加密后的密码；只有原电脑的原 Windows 用户可正常解密。
- `activity.log` / `.1`：滚动运行日志，不记录密码、登录请求、网页正文或完整认证链接。
- `BrowserProfile`：独立浏览器配置，可能含学校单点登录会话，请按个人登录资料保管。
- 自启注册表：`HKCU\Software\Microsoft\Windows\CurrentVersion\Run\GgsWifiAutoAuth`，内容为 EXE 的绝对路径及 `--background` 参数。

取消自启：取消勾选“开机自启”并保存。完全移除：先取消自启并退出，再删除 EXE；如需清除账号和单点登录会话，再删除上述配置目录。

## 构建与验证

在项目目录用 PowerShell 执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\test.ps1
```

使用 Windows 自带 .NET Framework C# 编译器，不下载 NuGet 包。测试使用模拟门户数据及本地浏览器测试页，不向学校提交账号密码，也不更改自启项。

若旧版 EXE 正在运行，可先退出旧版再构建，或传入 `-OutputName GGS-WiFi-v1.2.0-windows-x64.exe` 将新版另存；压缩包中的 `GGS_WIFI.exe` 为新版。

代码分为门户参数和网络检查 `src/PortalClient.cs`、后台浏览器认证 `src/BrowserLogin.cs`、登录切换 `src/AuthenticationFlow.cs`、设置/托盘/监测 `src/Program.cs`。
